版本: v7-multi-resolution-and-prompt-book
日期: 2026-05-14
特性: 📐 多分辨率白名单 + 📖 提示词手册

关键改动:
  - 目标分辨率从「单一字符串」升级为「白名单列表」, 多个用 ; 分隔
      默认值: 1920x1088;1088x1920;544x960;960x544
      留空 / "*" / "auto" / "any" = 任意分辨率 (不过滤, 取最新视频)
      也支持空格 / 逗号 / 换行做分隔; 大小写 X / × / * 都兼容
  - 后端接口接受新字段 target_resolutions (list[[w,h]] 或字符串均可)
      register_video / extract_tail_frame (方式B) 用 _match_any_resolution 匹配
      老字段 target_width / target_height 仍可用, 保持向后兼容
  - 节点 widget "target_resolution" 默认改为多分辨率字符串
      register_only_target_res 关闭后, 完全忽略分辨率, 取最新视频
      —— 这就是「不管是什么分辨率自动取最后一个视频」的实现路径
  - 前端 🎞 选视频抽尾帧弹窗
      复选框文案动态化: "只看目标分辨率: 1920x1088 / 1088x1920 / 544x960 / 960x544"
      ★ 标记按白名单 any-match, 不再写死单一分辨率
      hover 提示展开完整白名单
  - 节点新增按钮 📐 编辑目标分辨率(白名单)
      chip 增删 UI, 9 个常用预设快捷键
      (1920x1088 / 1088x1920 / 544x960 / 960x544 / 1280x720 / 720x1280
       / 1024x1024 / 832x480 / 480x832)
      "清空 = 任意分辨率" 一键关掉过滤
  - 节点新增按钮 📖 提示词手册
      左列表 + 右编辑表单, 支持新增 / 更新 / 删除 / 复制 / 搜索 / 标签
      持久化到 ~/user/auto_sequential_prompts.json (回退到本插件目录)
      数据全局共享, 不绑 controller_id
  - 后端新增 3 个接口
      POST /auto_sequential/prompts/list    body: {search?, tag?}
      POST /auto_sequential/prompts/save    body: {id?, title, content, tags?}
      POST /auto_sequential/prompts/delete  body: {id} 或 {all:true}

向后兼容:
  - 老工作流加载时, 如果 target_resolution = "1920x1088" 单值, 行为不变
  - 后端两条扫盘路径都做了字段双兼容: 优先用 target_resolutions, 没传回退到 target_width/height
  - 老工作流 register_only_target_res = True (默认) 行为完全不变
  - 没有破坏性的 widget 重命名或顺序调整

修复的根因:
  原版只识别 1920x1088 的根因: 单一 target_width/target_height 写死, 命中不上就
  返回 skipped_reason = "no_target_res_match", 前端虽然只 console.log 不报错,
  但「自动取最后一段视频末帧」这条链就断了。新版改成白名单匹配, 命中其一即可;
  关掉过滤 (register_only_target_res = false) 则完全忽略分辨率, 取最新视频。
